# 日常记账 App｜V0.1 开发计划

**制定日期：2026-10-18**  
**依据：** `需求文档/日常记账App-V0.1-需求文档.md`  
**技术方案：** macOS 原生 SwiftUI + Swift Package Manager + 本机 JSON 持久化  
**最低系统：** macOS 14  
**联网依赖：** 无

## 实现原则

- 金额使用整数“分”存储，避免浮点金额误差。
- 账户余额由初始余额和全部有效账目推导，不单独保存可漂移的余额字段。
- 转账同时影响转出和转入账户，不进入收入、支出和预算统计。
- 数据写入用户 Application Support 目录的本地 JSON 文件。
- 每个阶段先增加覆盖该阶段验收点的测试；测试通过后才进入下一阶段。
- 不删除测试、不跳过测试、不降低既定断言。

## 阶段 1：工程骨架与领域模型

实现账户、分类、账目、预算、月份等基础模型，以及人民币金额解析与格式化。

测试：

- 金额解析和格式化。
- 预设收入、支出分类完整性。
- 月份边界和月份切换。
- 模型 Codable 往返。

## 阶段 2：账务计算引擎

实现收入、支出、转账对账户余额的计算，并支持账目修改、删除后的重新计算。

测试：

- 收入增加账户余额。
- 支出减少账户余额。
- 转账同时更新两个账户且保持总余额不变。
- 停用账户仍保留历史余额。
- 修改、删除账目后余额正确。

## 阶段 3：月度统计与预算

实现按月汇总收入、支出、结余、分类占比、上月对比、支出前三分类及预算状态。

测试：

- 月份过滤和跨月隔离。
- 转账不计入收支。
- 分类汇总、排序和占比。
- 上月支出对比。
- 预算正常、接近和超出状态。

## 阶段 4：本地持久化

实现 JSON 原子写入、读取、首次启动默认数据以及损坏数据错误处理。

测试：

- 完整数据保存与读取往返。
- 空目录首次加载生成默认分类。
- 文件损坏时明确报错且不覆盖原文件。
- 保存文件仅位于传入的本地目录。

## 阶段 5：业务操作层

实现新增、编辑、删除账目，账户管理，分类迁移，预算设置及自动保存。

测试：

- 收支和转账录入校验。
- 编辑、删除后保存和统计同步。
- 已使用分类禁止直接删除。
- 迁移历史账目后允许删除分类。
- 停用账户不再作为新账默认候选。

## 阶段 6：macOS 界面与交付

实现三项主导航：月度概览、账目明细、账户；实现新增/编辑账目、转账、预算设置、分类与账户管理。

测试与验证：

- 业务层端到端流程测试。
- SwiftUI App 完整编译。
- Release 构建与 `.app` 安装包组装。
- 检查 App 包结构、Info.plist 和可执行文件。
- 启动验证。

## 最终验收

完成所有阶段后执行完整测试集和 Release 构建，任何失败都先定位和修复，再重新运行完整测试。
